# Implementation Plan: Full-Coverage Multi-Game Forecasting Platform

**Branch**: `001-full-coverage` | **Date**: 2026-07-30 | **Spec**: [spec.md](./spec.md)

## Summary

Ten audited defects in v2.1.0, of which four were structural. The plan treats the geometry
hard-coding as the root cause of the largest one and sequences everything else around it: once
`GameGeometry` exists as a single source of truth, metrics / contracts / theory / orchestration
can each be generalised independently and tested in isolation. The statistical layer is then
wired into the orchestrator, and the catalog is regenerated from upstream `__all__` so that no
count in the repository is ever hand-typed again.

## Phase 0: Research

Retrieve upstream `__all__` from primary sources rather than relying on training data, because

[research.md](./research.md).

## Phase 1: Design Decisions

**D1 — Two game families, not one.** A digit game is not a degenerate select game: repeats are
legal, there is no ascending constraint, and set overlap is meaningless. Modelling `digits` as
`select` with `k == n` would silently produce wrong metrics for ナンバーズ. `GameGeometry`
therefore carries a `family` discriminator and `inclusion_vector_length` differs by family
(`n` for select, `positions × n` flattened for digits).

**D2 — Contracts by factory, not by constant.** Pydantic `Field` constraints are class-level, so
`ge=1, le=37` cannot be parameterised in place. `contracts_for(game)` builds and caches the model
classes via `create_model`. The v1 `contracts.py` is left untouched so its regression tests keep
their meaning.

**D3 — Ranking needs per-draw losses.** Significance is not recoverable from a mean, so
`ModelResult` requires a loss vector and a model without one is `unranked` rather than ranked on
an aggregate. This is a deliberate capability reduction relative to v2.1.0, which would rank
anything.

**D4 — Romano-Wolf as the default correction.** All candidates see the same folds, so their
statistics are strongly correlated. Holm is valid but wastes most of its power on an
independence assumption that does not hold. Romano-Wolf bootstraps over draws (columns), which
preserves that correlation, and controls FWER under it.

**D5 — Champion may be `None`.** The type of `Leaderboard.champion` is `LeaderboardRow | None`.
Making it non-optional is what forced v2.1.0 to name `uniform` a champion.

**D6 — Unverified revisions stay `None`.** A fabricated commit SHA makes `protocol_hash` look
reproducible when it is not, which is worse than an explicit gap. `revision_status` surfaces
`UNPINNED` so the gap is queryable (`loto3 catalog --unpinned`).

**D7 — Only `ImportError` is a legitimate fallback.** Every other exception in optional-package
resolution indicates a real bug and propagates. This is what makes NFR-001 achievable.

## Complexity Tracking

| Addition | Justification | Cheaper alternative rejected because |
|---|---|---|
| Romano-Wolf bootstrap | correlated sweep; Holm loses most power | Holm alone would report zero discoveries even for a real effect |
| Adaptive conformal (ACI) | fixed split conformal collapses under drift | tested: fixed conformal coverage falls well below target on a drifting series |
| Two-family geometry | digit games need different metrics | one-family model produces silently wrong ナンバーズ metrics |
| Separate provenance gate | different remediation from range violations | merging into one boolean is what hid the v2.1.0 defect |
| Popularity module | only actionable finding from 8 PDCA cycles | omitting it discards the sole positive result |
