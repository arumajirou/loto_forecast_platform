# ADR-0003: 被覆KPIの判定軸をArm A（データ非依存被覆構成）との差に置く

- 状態: 採用
- 日付: 2026-07-30
- 関連: specs/003-kpi-lab/, reports/kpi-feasibility.md

## 文脈

`coverage/auto_research.py` は `target_coverage=0.90` / `tolerance=1` を目標に自律探索していた。
判定は `row_within_tolerance >= 0.90` の単独評価であり、口数上限 `max_candidates=5000` は可変だった。

計算により次が判明した（`combinatorics.bounds`）。

- ロト7で90%被覆に必要な最小口数は 4,237（パッキング下限、モデル独立）
- 一様i.i.d.抽選下で最適プールは被覆符号の構成問題であり、予測問題ではない

## 決定

1. KPIは口数を固定した上で `arm_delta = coverage(Arm B) - coverage(Arm A)` を主判定軸とする。
2. Arm A はデータを一切使わない被覆構成とする。これを完走させずにArm Bの結果を出さない。
3. 早期停止を anytime-valid e-process に置換し、`e_value >= 1/alpha` のみで勝利宣言する。
4. 「達成したがモデル寄与なし」「到達不能」を成功終端状態として一級市民にする。

## 根拠

Arm A なしでは、被覆率の由来がプール設計かモデルか分離できない。Arm A は封印抽選に対して
過適合が原理的に不可能なので、正しい帰無仮説になる。

`stop_when_target_met=True` は500試行の最大値を単一測定として報告する手続きであり、
名目閾値が誤り率を制御しない。e-process は Ville の不等式により連続的な閾値チェックを
α のペナルティなしに許すため、最適停止が正当化される。

## 帰結

- 過去の `row_within_tolerance` 結果とは比較不能になる（`kpi_definition_hash` が異なる）。
  憲章Vにより異なるprotocol間の比較は元来禁止されているため、追加の制約ではない。
- 「モデルに価値がない」が到達しうる結論になる。これは失敗ではない。
- `coverage/` は削除せず段階移行とした（対応表は specs/003-kpi-lab/spec.md §9）。

## 却下した案

**案A: 現行KPIを維持し口数上限だけ下げる。** 分母が明示されないため、報告を読む側が
口数を見落とすと性能主張と誤読される。構造で防げる問題を運用で防ぐことになる。

**案B: 費用正規化した単一スコアに統合する。** 被覆率・費用・完全一致確率は目的が異なり、
重み付けの選択が結論を決めてしまう。多重ゲート方式を採った。
